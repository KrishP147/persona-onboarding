# spec: what the onboarding has to do

build an onboarding for a persona style personal assistant that collects four things: a name for the agent, the user's name, a connected gmail, and something the user could use help with. it should try to collect everything except the agent's name over a phone call, and stay fully adaptive to text when the user won't or can't take the call.

people won't play by the rules. the agent has to be adaptive and conversational enough to survive any kind of user error: hanging up mid-call, refusing, going silent, rambling, changing their mind, giving everything at once, or trying to break it on purpose.

it shouldn't feel like a form. it should feel like a conversation, and the user can move through it early. the point of onboarding is to show the user the value the assistant can give them, so someone who already knows what they need can "graduate" into the main experience early. at the same time it keeps the user on track when it still needs something, and steers gently without being overbearing.

a web simulator of a phone with voice is enough; it doesn't need real phone numbers.
